# Excel Template (Mode A — "Value My Company")

Mode A accepts a single `.xlsx` workbook (max 10 MB). Download the starter template
from the Data page (**EXCEL UPLOAD → Download template**) or via:

```
GET http://127.0.0.1:8000/api/company/template
```

The template is generated by `backend/app/data/excel_template.py` and is designed so
the ingestion parser detects everything natively.

## Workbook structure

| Sheet | Purpose |
|---|---|
| **README** | Fill-in instructions, unit rules, required vs optional metrics |
| **Income Statement** | Revenue → EBIT → EBT → tax → net income, one column per period |
| **Cash Flow** | D&A, operating cash flow, CapEx, (optional) ΔNWC components |
| **Balance Sheet** | Assets, liabilities, equity, cash, debt, working-capital items |
| **Assumptions** | Optional starter values: tax rate, growth, margin, WACC inputs, terminal g, exit multiple |
| **Debt Schedule** | Optional: tranches, rates, maturities → cost of debt and debt mix |

## Rules the parser follows

1. **Period columns** — header row contains periods: `FY2020`, `2020`, `Dec-2020`,
   `FY2020A`, etc. One column per fiscal year; the parser orders them chronologically.
2. **Label column** — the first column holds line-item labels. Synonyms are matched:
   "Total Revenue", "Net Sales", "Revenues" → `revenue`; "Operating Income",
   "EBIT", "Operating Profit" → `ebit`; "CapEx", "Purchase of PP&E" → `capex`, and so on.
3. **Units inherit down a block** — if a header says `($ in millions)`, every value in
   that block is scaled ×1e6. Units are detected once per sheet/block, not per row.
4. **Signs are normalized** — outflows (CapEx, costs) are stored as outflows
   consistently; the audit later verifies revenue > 0 and CapEx sign after
   normalization.
5. **Cell provenance** — every extracted value remembers its origin as `Sheet!rowN`,
   shown in the Data Review source column. Nothing is anonymous.
6. **Required minimum** — `revenue` in the latest period is mandatory (the audit blocks
   without it). EBIT and shares outstanding may be supplied manually afterwards;
   missing shares leaves `implied_share_price` null rather than fabricated.

## Assumptions sheet format

Two columns: **label** and **value** (percent entered as `8.00` or `0.08` — both are
understood, stored as decimals). Recognized labels include:

- Tax rate
- Revenue growth (default forecast driver)
- EBIT / operating margin
- D&A % of revenue, CapEx % of revenue, ΔNWC % of revenue change
- Risk-free rate, beta, market risk premium (or "cost of equity" for manual mode)
- Pre-tax cost of debt
- Weight of debt / weight of equity (or leave blank to use market values)
- Terminal growth rate, exit EV/EBITDA multiple

Values parsed from this sheet become **USER_INPUT** (not overrides); the Assumptions
page lets you promote any of them to an explicit override later.

## Debt schedule format

Rows per tranche: name, balance, interest rate (or interest expense), maturity.
The parser aggregates balances into total debt and computes an implied weighted-average
pre-tax cost of debt = Σ(interest) / Σ(balance). If absent, cost of debt falls back to
the assumption sheet or a manual entry — never an invented rate.

## Validation on upload

Upload runs through the same validation agent as API data:

- unrecognized labels are ignored (not guessed),
- fields the parser could not find appear as **Missing** rows you can edit inline,
- currency must be consistent across periods (mixed currency = critical audit FAIL),
- statement ties (Rev − COGS = GP, EBT − Tax = NI, A = L + E) are checked with
  tolerances and reported — discrepancies are **not auto-fixed**.
